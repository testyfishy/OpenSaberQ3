# v0.6.0 release report

**Released:** 2026-11-06 | [GitHub release](https://github.com/testyfishy/OpenSaberQ3/releases/tag/v0.6.0-q3)
**APK:** `OpenSaberQ3-0.6.0.apk` (83,624,298 bytes, SHA-256
`ACCAA169C8DF85067600C33BF199C37C91C18AD4B1407E45F4D479C04074FB5A`)

v0.6 adds source tags, a source filter and BeatLeader scores, and includes the v0.5.1 chain fix.

## Library sources

Every map folder now carries an `OpenSaber.meta` sidecar with a schema version, a `source`
(`beatsaver`, `beastsaber`, `uploaded`, `local`, `unknown`), the BeatSaver map id and the level
hash. Downloads, manual uploads and the bench probe write it atomically (temp file + rename); a
missing, corrupt or future-schema sidecar reads as Unknown and never blocks the map. The sidecar is
separate from `Info.dat` because editing the map's own files would change the level hash.

![Library filtered to BeatSaver](images/v06-library.png)

The main menu gets a source selector beside the playlist picker, each row shows its tag, and the
Song Info panel names the source. The selection persists across launches. An empty filter says
"No maps match this source." and disables Play, Delete and Leaderboard rather than pointing at a
map that is not on screen.

## Backfill: old maps identify themselves

BeatSaver's version hash is the standard Beat Saber level hash: SHA-1 over `Info.dat` followed by
every difficulty file, in the order `Info.dat` lists them. That means a map downloaded before this
feature can be identified without re-downloading it.

On the menu, once per session, one map at a time:

1. compute the level hash from the folder;
2. ask `GET https://api.beatsaver.com/maps/hash/{hash}`;
3. write `source=beatsaver` + map id on a hit, or `source=unknown` + the hash on a 404.

A transport failure writes nothing, so a flaky connection does not brand a map Unknown forever.
The pass stops when the menu is hidden; nothing runs during play.

Device run on the real headset library: **13 maps queued, 10 tagged BeatSaver, 1 kept Unknown +
hash (not on BeatSaver), 2 skipped** because their `Info.dat` lists a difficulty file that is not
in the folder. The Phoenix hash computed on device matches its published
`bf2c367d29b133b66dc27f6f8e20467d0ec3301f`.

## BeatLeader

A read-only board for the selected map and difficulty, opened from the main menu. It uses the
documented two-call read path — the board for `{hash}/{difficulty}/{mode}`, then the top scores
ordered by rank — with a 10 s timeout, a per-session cache and no account. Nothing is submitted.

![BeatLeader top 10](images/v06-leaderboard.png)

The panel maps the local characteristic to BeatLeader's mode (Standard, OneSaber, NoArrows,
90/360Degree, Lightshow, Lawless) and shows rank, player, score, accuracy, PP and modifiers. It
distinguishes no hash, unsupported characteristic, not found, no scores and offline. A map without
a hash explains that it needs re-downloading from BeatSaver instead of failing.

Device probe against the live API: **Top 10 of 10 shown**, 10 rows, The Phoenix ExpertPlus /
Standard. The raw values are in [device-evidence.md](../specs/020-libs-leaderboards/device-evidence.md).

## Chain fix (from v0.5.1)

v0.5.1's root cause was the authored spawn animation: it scaled every chain link mesh to 10% and
pulled it 2 m back for 0.8 s, so each new link was a detached dash. Links now span their exact
segment, the mesh covers bends by half a width, the hitbox stays exact, and a test sweeps a blade
along a straight and a curved chain and cuts every link in head-to-tail order. White highlights at
the joints remain cosmetic.

## Play isolation

A 30 s dense-map bench with the backfill deliberately given work logged `queued 11`, one hash, then
`stopped at 0/11` the moment Playing began; no lookup or write followed, and BeatLeader was never
requested because the panel was not opened. The same run held **120 fps median, App 5.08 ms, GPU
0.87, 7 cubes peak** (Quest 3, default Performance preset, bot on that map). The backfill and the
panel are menu-only.

## Android export: JSON parsing workaround

In the exported APK, `JSON.parse_string` inside a static function of a `class_name` script returned
null for valid responses: every `Info.dat` hash failed and the BeatLeader board would not parse.
The cause is **unconfirmed** (other static JSON callers still work); the evidence shows only that
path failing. Map hashing now reads `Info.dat` through the loader map selection already uses
(`vr.load_json_file`), and the BeatLeader panel parses the HTTP body in its instance context. Both
carry a short comment; the follow-up is logged in the
[spec](../specs/020-libs-leaderboards/spec.md).

## Deferred

**BeastSaber as an import** is not in 0.6.0. BeastSaber has no public map API; it curates BeatSaver
maps and publishes `.bplist` playlists. The intended 0.6.1 feature is to accept a playlist URL or a
file already on the headset, resolve each entry through BeatSaver, download and tag it
`beastsaber` — pending a decision on how the playlist reaches the headset. The source label
already exists in the schema.
